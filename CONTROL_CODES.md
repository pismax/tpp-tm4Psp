# Tokimeki Memorial 4 PSP control-code reference

Verified 2026-11-03 against the supplied original text dump and the decrypted
NPJH50127 v1.01 executable used by the half-width patch. This reference separates
codes present in original messages from handlers found only in executable code.
It does not claim every code works in every menu or scenario context.

## Which length counts toward the budget?

**The ASB storage budget counts CP932 bytes before control-code expansion.**
It counts the literal code stored in the string, after export normalization.
It does not count the bytes, characters or pixel width of the replacement text
generated by the running game.

For example, if `\h00` expands to `星川さん`:

| Item | Stored bytes charged to the string | What the player sees |
|---|---:|---|
| `\h00` | 4: `5C 68 30 30` | A context-dependent name, such as `星川さん` |
| Literal `星川さん` | 8 in CP932 | Four Japanese characters |
| `Hi, \h00!` | 9 | `Hi, 星川さん!` in that context |
| `\i26`, `\j26`, `\k26` | 4 each | Player-name field of variable length |
| `\s`, `\r`, `\c`, `\x`, `\z` | 2 each | Context-dependent replacement |
| Literal `\n` | 2: backslash plus `n` | A line break in paths that process it |
| Actual LF newline | 1: `0A` | A line break |
| `%s` | 2 | A caller-supplied string, where the caller formats it |
| Renderer `\v100` | 5 | Timing change; no printed glyph for the code |

The example name's eight expanded bytes do **not** replace the four-byte token
in the original ASB slot. Expansion happens in separate runtime buffers.
A fixed 57-byte slot can therefore contain a four-byte name token plus up to
53 other encoded bytes, including any punctuation, newlines and other codes.
The terminating NUL is already reserved outside that reported 57-byte budget.
If CRLF is actually stored instead of LF, it costs two bytes per newline.

There are separate runtime and visual limits. A long replacement name can
overflow a line even though the stored token fits. The inspected substitution
routine uses 0x200-byte buffer regions/an input-scan bound; the scenario renderer
initialization passes a 0x400 character-record maximum. These are **not** a
guarantee that arbitrary large expansions are safe, and do not enlarge a fixed
ASB slot. Continue to test the expanded message in game.

Do not invent or replace codes merely to save bytes. Their replacements depend
on game state, and the add-on requires the source's controls to be preserved.
Version 1.2.5 permits omission of contextual `\hNN` address codes under the shared
name-code policy (Warn/Off), for natural pronoun-based dialogue. Changed selectors,
added/duplicated codes, other substitutions and printf arguments remain protected.

## Notation and safe editing

In the tables below, a backslash is one literal ASCII character in the cell.
`NN` means **exactly two decimal digits**, including leading zeros; it is not
hexadecimal. `\h10` selects decimal ID 10, not hexadecimal 0x10/decimal 16.
`H` denotes a hexadecimal digit only in the renderer's colour code.

JSON represents one backslash with `\\`. That serialization does not double
the game's byte cost. In the Translator++ cell, keep the single backslash
already present in the original. Do not assume that doubling it escapes a game
command safely.

Preserve the whole token, including letter, case, digits and arguments. Do not
translate `\i26` into `\i08`, add an honorific already supplied by the replacement,
or hard-code a player name. Keep multiple `%s` arguments in their required order.
The exporter checks token counts and their arguments, not whether a translated
sentence uses a variable in the correct grammatical role.

## Codes observed in the original scripts

Counts below come from 858 byte-distinct original ASB/TSID/CSV files containing
105,818 examined strings/fields. This includes internal fields and differs from
the add-on's smaller set of Japanese translation rows. The machine-readable
[inventory](control-code-inventory.json) records the observed variants.

| Code | Observed count | Meaning and confidence |
|---|---:|---|
| Literal `\n` | 2,642 | Line break. Confirmed in original system messages and byte-copy wrappers that convert `5C 6E` to `0A`. ASB also uses actual LF newlines. |
| `\hNN` | 3,527 | Contextual character name/address form. May include nickname or honorific, depending on character, relationship and speaking context. It is **not** an icon code. |
| `\iNN` | 40 | Last/family-name form. `\i26` is the player's surname; `\i08` is also present. Executable field access confirms this distinction. |
| `\jNN` | 6 | First/given-name form. Original occurrences are `\j26`, often after `\i26`. |
| `\kNN` | 12 | Full-name form. Original occurrences are `\k26` in player introductions. |
| `\mNN` | 3 | Generic male-classmate name, selector 01–03. Original scripts use `\m01` and `\m03`; the data provides 男子Ａ/Ｂ/Ｃ. |
| `\pNN` | 37 | One of three context-selected place labels, 01–03, looked up through `spot1_spot1.mes_name`. Original scripts use `\p01`/`\p02`; do not assume a fixed place globally. |
| `\r` | 22 | Context-selected outing/destination label. The inspected path uses `spot1_spot1.offer`, with a special seasonal ski fallback. **Not** carriage return. |
| `\s` | 42 | Context-selected date, expressed using month/day or relative-month wording. Original usage includes invitations and arrangements. **Not** a generic space code. |
| `\c` | 3 | Context string used as the selected exam/career target in the observed scenario. The handler copies an object text buffer; the exact value is scene-dependent. **Not** a colour command at this substitution stage. |
| `\x` | 1 | Player surname plus `さん`. Confirmed by player surname access and appended constant; original script uses it in a self-introduction. |
| `\z` | 2 | Numeric amount from game variable `v_t_125`, rendered with full-width digits. Original text uses it for allowance awarded in リッチ. Do not assume it always means the current wallet balance. |
| `%s` | 59 | Caller-supplied string formatting. Distinct from the backslash substitution routine; preserve where the original caller expects it. |

For classified ASB message boxes with reflow enabled, literal `\n` controls may
be added or removed within the maximum line count and width. Exact-line mode,
unclassified ASB strings and tables keep their original newline structure.
Other control codes and arguments remain protected in every mode.

The literal-newline count includes six cases followed immediately by ASCII
words such as `\nPSP`; the command is still just `\n`. `PlayStation`/`PSP` etc.
are following text, not newline arguments.

Examples of original code structure:

```text
\i26 \j26          family name + a stored space + given name
\k26              full name supplied by the game
\h00              Hoshikawa's context-appropriate address form
\sに\p01で…       selected date and one selected meeting place
```

The space between `\i26` and `\j26` consumes an additional byte if ASCII, or
two if it is a full-width Japanese space. The code does not make adjacent
punctuation or whitespace free.

`\iNN`, `\jNN`, `\kNN` have handlers for 00–18 and 26; data availability and
fallbacks vary by character. Do not assume they support the special 23–25 slots
that `\hNN` handles. IDs 19–22 are not handled as normal names by this dispatch.

The common selector decoder reads two bytes using decimal-digit arithmetic and
maps an out-of-range result to 00. It does not robustly validate that both input
bytes are digits. Consequently, malformed strings can unexpectedly select a
different character instead of raising an error. `\hey` computes an out-of-range
selector and falls back to 00, explaining the earlier accidental Hoshikawa
insertion. Invalid/hexadecimal-looking codes are not a supported translation trick.

## Additional substitution handlers found in the executable

These cases exist in the same dispatch table but were **not observed as codes
in the scanned original message corpus**. Their code paths were inspected;
their results have not all been visually tested. Preserve existing usage if
encountered elsewhere; do not add them speculatively to a translation.

| Code | Inspected behavior |
|---|---|
| `\g01`–`\g03` | Generic female-classmate names from char_001–003: 女子Ａ/Ｂ/Ｃ. This is not the main heroine ID namespace. |
| `\dNN` | Date string selected through a context/date manager, with current-date fallback. Exact meaning of each index needs contextual testing. |
| `\e` | Context-selected event/category name via `event_category_name.ectfile`. Exact scene output needs testing. |

The inspected substitution routine recognizes the letters
`c d e g h i j k m p r s x z`. Other letters pass through this layer; a later
wrapper or renderer can still interpret some of them. Thus absence from this
dispatch does not prove a sequence is safe literal text in every game path.

## Lower-level scenario renderer controls

The later character-record builder has three additional escape handlers. These
are distinct from the higher-level substitutions above. Some strings bypass
the substitution layer; ordinary scenario strings may not. In particular,
`\s` and `\c` can be intercepted as date/target substitutions **before** reaching
this renderer, so inserting a colour/style example into an ASB translation is
not established as safe.

| Renderer syntax | Stored length | Verified implementation; limitations |
|---|---:|---|
| `\sNN` | 4 with two digits | Reads up to two decimal digits and sets a per-character byte attribute, initially 16. Likely size/style-related, but its visible effect was not established. Do not label it a guaranteed font-size command. |
| `\vNNN` | 5 with three digits | Reads up to three decimal digits into per-character reveal-timing weight, default 100. Zero is raised to 1. Smaller weights reduce the subsequent time allocation. Exact perceived timing depends on the message's base speed. |
| `\cHHHHHHHH` | 10 | Reads up to eight hex digits into a packed colour, adjusts each component and stores it with subsequent character records. Channel ordering/visual result were not verified, so do not assume CSS-style RGBA. |

Their argument parsers can accept shorter numeric runs, but use and preserve
the complete original token. The examples above describe parsing, not a
recommendation to insert new controls. Actual LF is stored as a newline record;
printable CP932 characters are decoded before these renderer escapes.

## Percent formats and things not confirmed

Only `%s` was observed as a percent placeholder in the scanned source strings.
The executable also contains ordinary printf-style numeric format strings such
as `%d`, but that does not establish `%d`, `%02d` or `%%` as universal commands
in every dialogue cell. Preserve such formats if present in a particular source
and supported by its caller; do not invent them based on generic C conventions.

No general RPG Maker-style wait, name, colour or variable syntax has been
established for this game. Do not assume `\r` means carriage return, `\t` means
a supported tab command, or `\h` inserts a fixed name without a selector.
There is no confirmed universal icon command in this inventory.

## Export validation and the CP932 backslash trap

Version 1.1.2 preserves numeric arguments for all the documented name/context
selector families, plus the renderer arguments; changing `\i26` to `\i08`,
for example, is rejected. This corrects the earlier generic matcher, which
protected some command letters without protecting all their numeric suffixes.
It still compares the actual source controls, rather than globally allowing
new commands in arbitrary translations.

The substitution/newline layers scan bytes without skipping CP932 trail bytes.
Some ordinary Japanese-encoded characters end with `5C` (backslash): horizontal
bar `―` is `81 5C`, and `ソ` is `83 5C`. Followed by a recognized escape letter,
they can accidentally form a command across a character boundary.

The exporter converts Unicode em dash to ASCII hyphen and rejects translated
trail-byte collisions before these byte-oriented prefixes:
`c d e g h i j k m n p r s x z`. Genuine authored control codes are unaffected.
The renderer's `\v` handler is CP932-aware; it is not included in that particular
trail-byte guard. The earlier `—hey` → `＄川さん` incident and its verified fix
are explained in [the investigation](plan/half-width-and-ppsspp.md).

## Evidence and verification

Primary evidence is the original game data and its decrypted executable, not
guesses based on command letters:

- Inventory: [control-code-inventory.json](control-code-inventory.json).
- `char_char.dat`, `girl_*_name.dat`, `mate_*_name.dat`: identity/name fields.
- Guest `08850270`: byte-oriented substitution routine.
- `08850354`–`08850384`: two-byte decimal selector arithmetic and range clamp.
- Dispatch table `08adfcf8`, covering letters `c`–`z`; unhandled letters route
  to the pass-through case. Individual handler addresses were recorded locally.
- `0886b0d4`: example wrapper converting literal `\n` into LF.
- `08871310`: CP932-aware character-record builder, with `s`, `v`, `c` branches.
- `088719dc`/`08871a80`: scenario initialization and 0x400 record-count argument.
- `python/tm4_bridge.py`: export encodes/rebuilds strings and checks their byte
  lengths without executing or expanding the controls.

Addresses apply only to the fingerprinted executable used by this add-on.
The investigation's [profile and checks](plan/half-width-and-ppsspp.md) identify
that file. Original binaries and raw dialogue dumps are not distributed here.
